# Built-in Personas Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a built-in cast of personas that a person can pick per role
(Host, Reader), so the briefing's voice and wording come from a named
character without the user building HA conversation agents.

**Architecture:** A new `personas.py` holds the catalog as data plus a
deterministic daily pick. `build_segment_step` resolves each role to a
persona and writes four step keys (`voice`, `voice_personality`,
`voice_profile`, `openai_voice`). The generator passes the last two to
`async_synthesize_speech`, which sends `voice_profile` to Gemini as the full
director profile and `openai_voice` to OpenAI unmapped. The person form
gains two multi-select fields.

**Tech Stack:** Python 3.13, Home Assistant custom integration, pytest
(`pytest-homeassistant-custom-component`), ruff.

**Spec:** `docs/superpowers/specs/2026-10-25-personas-design.md`

## Global Constraints

- Public HACS repo: no personal names, places, zone ids, sensors or
  household details anywhere (catalog, code, tests, commits). Tests use fake
  values (Alex, Sam, `media_player.kitchen_speaker`). Before each commit the
  controller greps the staged diff with its private term list (kept out of
  the repo) and expects no match.
- No behaviour change for a person who selects no personas: same voice,
  same `voice_personality` string to the writer, same Gemini prompt text.
- The persona never names itself; no persona name appears in narration
  rules or on the display card.
- Shipped personas must not name or describe a real person.
- Checks per task: `python -m pytest -q -p no:cacheprovider --timeout 60`,
  `ruff check custom_components tests`, `ruff format custom_components tests`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A saved persona id that is no longer in the catalog → that id is
   skipped; if none remain the role behaves exactly as today. (Task 1, Task 3)
2. A persona id saved for the wrong role (the form allows custom values) →
   ignored for that role. (Task 1)
3. A person who picked personas *and* typed Advanced voice/personality →
   the persona wins for that role. (Task 3)
4. Gemini TTS fails while a persona is active → the HA TTS fallback still
   runs with the persona's voice name and no crash. (Task 2)
5. The all-heard clip and closing (built from the closing step) use the
   Host persona, and the daily text uses the Reader persona. (Task 3)

def test_pick_single_and_stable_daily():
    day = date(2026, 1, 5)
    assert pick_persona(["arthur"], ROLE_HOST, "p1", day).persona_id == "arthur"
    ids = ["arthur", "theo", "ray"]
